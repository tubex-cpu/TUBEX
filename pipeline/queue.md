# 制作キュー

現在の定期Routineは `routine_assignments.json` の明示割当だけを扱い、キューから案件を自分で選ばない。キューの直列処理順は設定担当が割当を決める際の判断基準である。指示の優先順位は保存済みRoutine指示 → 採用ref → 起動時main。STOPでは着手せず報告。ASSIGNMENTS_REQUIRE_GATE_CHECKは制作許可ではなく、割当と承認根拠の照合を要する。実行権取得スクリプトは採用refのhead・差分なしの独立worktree内で実行する。

チャンネルごとに上から順に処理する。複数のチャンネルが進められるときは、表の上のチャンネルを先に進める（利用上限で途中終了しても最優先が進むように）。Routine は各チャンネルとnoteの着手可能な案件を直列で処理する。1起動1工程の制限は廃止し、工程完了ごとに監査・承認・依存条件を再確認して、進められる次工程または独立案件を続ける。利用上限・重複実行・全件待ち・前進不能で保存して終了し、待ちの無限再確認はしない。承認・監査待ちの案件を飛ばし、独立した他案件へ進む。ゲート0／N0前の後続制作には進まない。
作業前に必ずそのチャンネルの `channels/<name>/CHANNEL.md` を読む。エピソード ID は `<チャンネル>-<連番>-<英語スラッグ>`（例：`habi-002-proto-elamite`）。note は `notes/note-<連番>-<英語スラッグ>/`。
