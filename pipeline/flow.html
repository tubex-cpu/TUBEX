台本（5）をサムネ（6）より先にするのは、サムネで約束した内容が本編で回収されているかを監査で確かめるためです。

監査のルール

判定は2択

「合格」か「差し戻し」だけ。合格するまで次の工程に進みません。

監査役は直さない

指摘するだけ。直すのは必ず作った側です。

3回で社長へ

同じ成果物で差し戻しが3回続いたら、AI 同士の堂々巡りを止めて社長に判断を仰ぎます。

毎朝の自動サイクル

8:52 自動起動

Claude Code が進捗表（STATUS.md）を読み、次にやる工程を決める。

作る・直す

工程を実施し、Codex の差し戻しがあれば全部直す。GitHub の PR に上げる。

Codex に依頼

PR に「@codex review」で監査を、サムネ工程では作成を依頼する。

Codex が判定

合格か差し戻しかを PR に書く。サムネは Codex が作り、Claude が監査する。

ゲートで社長へ

企画と完成品のときだけ、PR で確認依頼が届く。承認すると翌朝から次へ。

利用上限に達した日は何もせず止まり、翌朝に再開します。

追加費用ゼロの約束

Claude はサブスク枠内のみ（追加使用量 OFF） Codex はプラン枠内のみ（クレジット購入なし） API キーを使わない GitHub Actions を使わない 有料素材・有料音声を使わない
